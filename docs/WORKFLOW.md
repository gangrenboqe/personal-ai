# 每轮工作模板（WORKFLOW）

> 把"改之前先想清楚、改完必须验证"固化成可重复的流程。
> 这个项目既是作品也是证据——**能被验证比功能多更重要**。

---

## 改之前：先写清楚三件事

1. **要什么**：一句话说清这次改动解决什么问题。
2. **不算完成的条件**：什么情况算没做完（例如"只是看起来像好了"）。
3. **怎么验证**：用什么命令 / 什么日志 / 什么第三方留痕来证明。

> 如果第 3 条写不出来，说明这个改动没法被验证——那就先别改，或者先补上验证手段。

---

## 改之中

- 一次只改一件事；改完立刻验证，再动下一件。
- 任何"为了先跑起来"的临时处理，都要留 TODO 或写进 Roadmap，**不许悄悄留下**。
- 密钥、个人信息绝不进代码与 commit。

---

## 改之后：必跑

| 改了什么 | 必须跑什么 |
|---|---|
| Python 代码 | `python scripts/smoke_test.py` → **32/32 全通过** |
| 前端 | 浏览器实测（不是"打开页面就算"），确认交互真的生效 |
| 真实模型调用 | 期望「是否离线兜底：**否**」；网关侧日志出现 HTTP 200 |
| 文档 | grep 一遍数字与命令，确认和产物对得上 |

---

## 三条踩过坑换来的硬规则

1. **不要用"打开页面"证明工作完成。**
   要看日志：网关调用日志（HTTP 状态 / 耗时 / token）、数据库的 `messages` 表。
2. **"看着对" ≠ "能用"。**
   任何交给第三方系统的东西（PDF、导出件、上传件），必须验证**对方系统能不能读**，
   不能只验证人眼看着对。（这一条的代价见同作者的 `pdf-delivery-audit`）
3. **估算不算数。**
   排版高度按字宽估算会偏 18mm（约 4 行），足够翻页。能用真引擎就别用估算。

## 记录

每轮结束追加到 `CHANGELOG.md`，写清：**改了什么 + 被什么证据证明过**。
